# Инфраструктура при нулевом бюджете (проверено 2026-10-15)

Стек: Python + FastAPI, БД — Neon, сайт — Vercel Hobby. Без карты.

## Что умеет Vercel Hobby

| Что | Лимит | Значение для нас |
|---|---|---|
| FastAPI | Поддерживается нативно (preset `fastapi`, `app.py` / `app/main.py`) | Сайт и API — одна Python-функция |
| Длительность функции | 300 с, больше нельзя | Полный прогон воркера (20 игр + LLM) не влезает надёжно |
| Cron | **Раз в сутки**, точность ±59 мин. `0 * * * *` падает на деплое | Ежечасный запуск средствами Vercel невозможен |
| Vercel Schedules (`@vercel/schedules`, beta) | Hourly на Hobby похоже разрешён (jitter 15 мин) | TS-SDK, бета, для Python не задокументировано. Не опираемся |
| Active CPU / память / вызовы | 4 CPU-ч / 360 ГБ-ч / 1 млн в месяц | Ожидание I/O не считается в CPU; нам хватает с запасом |
| Тело ответа | 4,5 МБ | Не проблема |
| Логи | 1 час | Логи прогонов храним в своей БД |
| Использование | Только некоммерческое | Тестовое задание подходит |

При превышении лимитов Hobby фича блокируется до конца 30-дневного окна; денег не списывают.

## Neon Free

- 1 ГБ на проект, 100 CU-часов в месяц на проект, карта не нужна, pgvector есть.
- Scale-to-zero через 5 минут простоя, отключить нельзя. Холодный старт ~0,5–1 с.
- **CU-часы — реальное ограничение.** Минимальный размер 0,25 CU; если БД не засыпает
  вообще, это ~182 CU-ч в месяц, почти вдвое больше лимита. Отсюда правила:
  - не пинговать БД по расписанию чаще, чем раз в ~15 минут (никаких uptime-мониторов на эндпоинты с БД);
  - прогон воркера держать коротким, с LLM работать вне открытого соединения;
  - страница мониторинга опрашивает статус, только пока она открыта.
  Оценка: 24 прогона × ~8 мин бодрствования ≈ 25 CU-ч в месяц плюс просмотры сайта.

## Бесплатные LLM (лимиты из документации, сверить в кабинете)

| Провайдер | Модель | Лимиты free | Комментарий |
|---|---|---|---|
| Groq | gpt-oss-120b / qwen3.8-27b | 30 RPM, 1K RPD, **8K TPM, 200K TPD** | Быстро, но токенов мало: ~2 резюме в минуту, ~60 в день |
| Groq | whisper-large-v3-turbo | 20 RPM, 2K RPD, 7 200 с аудио в час, 28 800 с в день, файл ≤25 МБ | Подходит для расшифровки летсплеев (доп. часть 1) |
| Gemini | Flash-Lite | Цифры в блогах расходятся (~500–1000 RPD). Официальной таблицы нет | Основной кандидат по объёму. Проверить при регистрации, просит ли карту |

Нагрузка: максимум 480 игр в сутки, но большинство из SEE ALL без отзывов, и LLM для них
не вызываем. Резюме пересчитываем только при изменении набора отзывов (хэш). Реально
выходит десятки вызовов в день. Нужен адаптер с фолбэком между провайдерами и одним
вызовом на игру (JSON с двумя резюме).

Эмбеддинги для похожих игр — локально в воркере (`fastembed`, ONNX, без API), хранить в
pgvector.

## Предлагаемая схема

```
GitHub Actions (cron "17 * * * *" + workflow_dispatch)
   └─ python -m worker  ── Metacritic API ──> Neon (games, runs, progress)
                        ── LLM API (Gemini / Groq)
Vercel (FastAPI + Jinja2/HTMX)
   ├─ список, карточка, фильтр, поиск, сортировка  ── читает Neon
   ├─ /monitor: опрос /api/status каждые 2–3 с      ── читает runs/progress
   └─ кнопка «Запустить»: POST → GitHub API workflow_dispatch (fine-grained PAT, Actions: write)
```

Почему воркер в GitHub Actions, а не в Vercel:
- нет лимита 300 с (до 6 часов на job), можно ждать rate-limit LLM и ставить тяжёлые
  зависимости (fastembed, yt-dlp, ffmpeg);
- для публичного репозитория минуты бесплатны и не ограничены (для приватного — 2000 мин
  в месяц: при ежечасных прогонах по 3–5 минут это на грани);
- нюансы: `schedule` в Actions может опаздывать на 5–30 минут и пропускаться под нагрузкой,
  а через 60 дней без активности в репозитории отключается. Для точности можно добавить
  внешний бесплатный cron (cron-job.org), который дёргает `workflow_dispatch`.

Запасной вариант без GitHub Actions: cron-job.org раз в час вызывает `/api/cron` на Vercel
с секретом, а работа режется на порции ≤250 с с очередью в БД. Хуже: дробление, лимит
300 с, и каждая порция будит Neon.

## Что не проверено

1. **Пускает ли Metacritic с IP облаков** (Vercel = AWS `iad1`, GitHub Actions = Azure).
   С домашнего IP всё работает. Нужен зонд с каждого из двух мест.
2. YouTube с IP GitHub Actions: yt-dlp и youtube-transcript-api с облачных IP часто
   получают «Sign in to confirm you're not a bot». Это риск для доп. части 1.
3. Точные лимиты Gemini free и требование карты при регистрации.
